# payload-skills

Collection of practical checklists and implementation notes for **Payload CMS** with **Next.js** (media setup, security, auth, links, popups, tracking, forms, and styling). Each topic lives in its own folder under `description.md`.

## Markdown files

### Must have

Foundation for **every** Payload + Next.js project: setup, deploy stability, security, forms and mail, performance, SEO, and core styling. Work through these on every project regardless of feature scope.

| Document | What it covers |

| [payload-start/description.md](payload-start/description.md) | Bootstrapping a new Payload site (target: **Dokploy on Hetzner**): upload limits, WebP/Sharp resize, **`@payloadcms/storage-s3`**, proxy/body limits for large files, then the production build — a full `next build`, with the two-step `experimental-build-mode` kept only as a fallback for when the build cannot reach the database. |
| [static-rendering/description.md](static-rendering/description.md) | Getting **real static rendering (SSG)** out of Payload + Next.js on Dokploy: why the two-step build switches the route cache off entirely, `generateStaticParams` across a `[locale]` parent segment, how middleware rewrites drop runtime renders out of the cache, locale-aware `revalidatePath` (including the `media` collection, whose missing hooks let a replaced file 404 behind a still-warm CDN cache), and splitting `DATABASE_URI` between build and runtime. With measured numbers. |
| [image-optimization/description.md](image-optimization/description.md) | Serving images off-server via a shared **imgproxy** instead of the `next/image` optimizer (the self-hosted OOM/crash-loop cause): Dokploy **imgproxy + nginx-cache** Compose, **Cloudflare** settings (`Vary: Accept`, cache-everything, don't-cache-4xx, rate-limit), Next.js loader integration (`@morgendigital/next-imgproxy`) for the four render cases + SVG handling, plus the gotchas (no `f:auto`, loader in Server Components, absolute `getMediaUrl`, `unoptimized`). |
| [media-webp-variants/description.md](media-webp-variants/description.md) | Why `formatOptions` belongs on **every `imageSize`**, not just the collection: on the collection it converts the main file only, so the derivatives keep the upload's format — and the derivatives are what `next/image` serves. A PNG upload yields a WebP original and PNG variants, invisibly. With measured numbers (315 of 349 media affected, 101 MB; an `xlarge` at the original's own dimensions weighing 893 KB against 91 KB), a repair script, the two traps (`overwriteExistingFiles`, `payload run` swallowing argv), and the matching `sizes` attribute — including why the website template's own `sizes` default is invalid and therefore silently behaves like `100vw`, with a measured candidate-selection table and per-usage values. ⚠️ Corrects Todo 1.2 in `payload-start`. |
| [server-actions-encryption/description.md](server-actions-encryption/description.md) | Fix for recurring **"Failed to find Server Action"** errors on self-hosted (Dokploy) deploys: Next.js regenerates the Server Action encryption key on every `next build`, so redeploys/open tabs/multi-instance break. Set a stable **`NEXT_SERVER_ACTIONS_ENCRYPTION_KEY`** (`openssl rand -base64 32`) in the Dokploy env (present at build), plus optional `deploymentId` for version-skew hard reloads. Dev noise is harmless. |
| [security-check/description.md](security-check/description.md) | Pre-deployment security checklist for Next.js, Payload, and hosting: HTTP headers, env/secrets, CORS, rate limiting, file uploads, admin hardening, and infrastructure basics. |
| [form-submissions-email/description.md](form-submissions-email/description.md) | Mandatory setup for **every project with public forms** (contact, job applications): every submission gets its own **collection** (the mail is the notification, never the storage), uploads go into a **separate access-controlled collection — never `media`**, and the files are **always attached to the notification mail**. Email adapter is env-switched: **Resend by default** so something always works, **customer SMTP** the moment they hand over credentials — an env change, not a code change, so it can't be forgotten at go-live. Plus `replyTo`/SPF/DKIM, `mailStatus` on the document, the 40 MB Resend cap, and the retention job. |
| [email-test/description.md](email-test/description.md) | Gegenstück zu `form-submissions-email`: **prüfen, dass der Versand läuft — und mitbekommen, wenn er aufhört.** Getrenntes `verify()` und Testversand über `pnpm test:smtp` (Empfänger immer `@northlight.at`, zweite Env via `DOTENV_CONFIG_PATH` statt `.env`-Umbau), `secure` **aus dem Port abgeleitet** statt frei danebenstehend (465 implizit, 587 STARTTLS + `requireTLS`), und eine Zuordnungstabelle der wiederkehrenden Meldungen — `wrong version number` (TLS auf Klartext-Port), `535 5.7.139` (M365-SMTP-AUTH gesperrt), `5.7.60 SendAsDenied` — inklusive der M365-Eigenheiten (kein Port 465, PowerShell-Freischaltung, **Basic-Auth-Ende 2026**). Kern ist der **Laufzeit-Alarm über Resend an `office@northlight.at`** (eigener Agentur-Account über `ALERT_RESEND_*`, nie der Kunden-Key), gedrosselt auf eine Mail pro Ursache und 6 h, weil ein defekter Kunden-SMTP sich sonst wochenlang nur ins Container-Log schreibt. |
| [performance/description.md](performance/description.md) | Next.js performance cheat sheet: bundle analyzer, `serverExternalPackages`, `optimizePackageImports`, `dynamic()` code-splitting, ISR `revalidate`, image cache TTL + LCP `priority`, parallel/cached fetching (`cache()` / `unstable_cache`), on-demand revalidation (`revalidateTag` / `revalidatePath`), `<Suspense>` streaming, and Turbopack build cache — plus a per-project quick checklist. |
| [seo/description.md](seo/description.md) | Onpage-SEO cheat sheet: why `@payloadcms/plugin-seo` leaves `meta.*` empty (auto-generate is a manual admin button) and the frontend fixes that clear the recurring crawler findings — **title fallback** (`meta.title \|\| doc.title`) for missing/duplicate `<title>`s, **canonical URLs** in `generateMeta` (with a `path` param for prefix collections like `/posts/…` plus `/` vs `/home` dedupe), the OpenGraph `url` `/`-bug, **required `Media.alt`**, plus `generateDescription` and `metadataBase`/`lang`/H1 notes — and the **sitemap rule: every collection with a public route needs its own `<slug>-sitemap.xml` route, cache tag, `revalidateTag` in the hook, and an `additionalSitemaps` entry**, all locales included. `next-sitemap` excludes `/*` in the template and cannot discover DB-driven routes, so a new collection silently never gets indexed (measured: posts, apartments, news, campaigns missing across four projects). |
